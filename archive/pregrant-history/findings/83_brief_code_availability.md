# 83 — BRIEF-family artifact availability audit

## Immutable tree

The combined BRIEF repository is pinned at `077943328a555f49925ac1d459e00ed229bc63b9`
(9 April 2026). A metadata-only inspection found 601 files, 347 source-code files, and 45 data-like
files. No working tree was checked out and no third-party code was imported or executed.

The headline counts are misleading without subtree attribution: 492 files are a vendored Axolotl tree.
The historical BRIEF subtree contains 49 files; BRIEF-Pro contains 523 including Axolotl, leaving about
31 paper-specific non-vendored files. Current HEAD postdates both reviewed paper versions and is not an
author-declared immutable experiment revision for either.

## Rights and reproducibility

There is no repository-root license. Visible text licenses live inside vendored Axolotl/integration
subtrees and do not cover BRIEF/BRIEF-Pro source, scripts, prompts, or data. A `license.svg` is a website
asset, not an affirmative root grant.

Old BRIEF pins a Python/CUDA package list but not a base image, model revisions, or dataset derivations.
BRIEF-Pro splits training, vLLM, and LongBench across different environments; one conda file contains an
absolute `/data2/...` machine prefix. Evaluation still downloads and converts external LongBench files.
Hugging Face model/data links exist but immutable Hub revisions and complete derivation/checksum/rights
manifests are not established here.

The source tree also contains generated bytecode and a credential-named JSON path; its contents were
deliberately not inspected or exposed. Any future fixture must be secret-free and rebuilt from qualified
source artifacts. Released responses/compressor outputs cannot become Speck held-out evidence without
split and contamination audits.

## Decision

BRIEF and BRIEF-Pro remain mandatory conceptual baselines. Their combined tree does not authorize
execution, reuse, historical reproduction, or use of released outputs as held-out evidence. IterCOMP
and STEC declare no dedicated implementation. The twelve-source code ledger still has only one root-
rights-qualified code path and zero newly qualified reproductions; novelty and architecture decisions
do not change.
